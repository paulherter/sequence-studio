# Oracle: golden outputs from the frozen Swift tree

Plan section 1.1 and 0.3. Rust must match what the Swift code produced; goldens are recorded once and committed, so the daily loop needs no Swift toolchain.

## Layout
```
oracle/<crate>/
  run                  entry point, exit 0 = parity (Windows: run.ps1). Called by `cargo xtask gate <crate>` from the repo root.
  README.md            what the dump covers, how it was recorded (date, Swift tag, machine), known divergences policy
  inputs/              test inputs, small and deterministic (generated by gen_inputs.py when possible, never real user media)
  golden/<case>.txt    canonical dump per input, recorded from Swift
  known-divergences.txt  one input name per line, with a `#` comment line above explaining why Rust differs on purpose or by platform
  swift-dump/          the Swift dumper: main.swift + build.sh (plain swiftc against the package sources, or a SwiftPM tool under Tools/)
```
Big or binary inputs (media, real projects) stay outside the repo; `run` skips them with a note when `SQ_ORACLE_EXTRA` does not point at them. `inputs/` and `golden/` are binary in `.gitattributes`.

## Dump format (copied from the pilot, `crates/sq-prproj-reader/src/bin/dump.rs`)
- Plain UTF-8 text, LF, one record per line: `KEYWORD field field ...`. Same format printed by the Swift dumper and the Rust `dump` bin of the crate; the harness diffs them byte for byte.
- Strings are quoted and escaped: every scalar outside 0x20-0x7E, plus `\` and `"`, becomes `\u{hex}`. This makes the dump independent of normalization and encoding.
- Binary data is never printed whole: `<length> <fnv1a-64 hex>` (FNV-1a 64, offset 0xcbf29ce484222325, prime 0x100000001b3).
- Results are `ok <fields>` or `error <caseName>` using the Swift error case names; a Swift crash or an unsupported path prints a fixed marker line (`XML nil`) so the diff stays line based.
- Order must not depend on hashing: sort keys by UTF-8 bytes, iterate trees depth first in document order, print the depth as a number.
- Floats: print with a fixed format (`%.9g` equivalent written the same in both dumpers) or as raw IEEE bits (`f64:0x...`) when the card demands bit equality; the compare tolerance per crate is in its card.
- Images/audio: dump size + FNV hash for exact cases; for float renders store the PNG/WAV golden and let the Rust test compare per-channel max diff, failing-pixel share and FLIP with the thresholds in the card.
- Large dumps (> 1 MB) are stored gzip-compressed (`golden/<case>.txt.gz`) and compared after decompress.

## Recording (Swift side, on the Windows test PC)
1. Check out the tag `swift-baseline` on the PC (portable path is the reference, plan section 8.0). Do not edit Swift sources.
2. `oracle/<crate>/swift-dump/build.sh` builds the dumper; `oracle/<crate>/record.ps1` (or `record.sh`) runs it over `inputs/` and writes `golden/`.
3. Commit inputs and goldens in one commit "Record oracle for <crate>" with the tag and machine in the message body. A golden is replaced only by a new such commit, never edited by hand.
4. If the Apple path differs from the portable path, record both (`golden/` and `golden-apple/`); only `golden/` gates. The difference list goes to the card.

## Parity run (Rust side)
- `oracle/<crate>/run`: builds the Rust `dump` bin (`cargo build --release -p <crate>`), runs it over every input, diffs against `golden/`, prints counts (compared / known / diffs) like the pilot's `parity/run.sh`, exits non-zero on any unexplained diff.
- Fuzzing for parsers: mutate inputs deterministically (seeded), compare Rust against the Swift dumper while it still exists, and add every crash or diff as a new input plus golden.
- Known divergences are listed, justified and reported on each run; they do not fail the gate. A new entry needs a human or Opus decision.
- The pilot is the template: `crates/sq-prproj-reader/parity/` (gen_fixtures.py, fuzz.py, run.sh, known-divergences.txt). Move it to `oracle/sq-prproj-reader/` once goldens are recorded.
